# 开发与验证

## 开发

```bash
node --test "tests/*.test.js"     # 主入口（Node 原生测试运行器）
node scripts/run-tests.mjs        # 沙箱兜底：同进程顺序 import，不派生子进程
node tests/codegen.test.js        # 单个文件也能直接跑
```

> 在受限文件沙箱下这个 spawn 会被拒（EPERM），兜底 runner 改成同进程顺序 import。

> ⚠️ **两个 runner 的差别会咬人**：`node --test` 给每个测试文件派生一个进程，
> 而 `scripts/run-tests.mjs`（沙箱兜底）是**同进程顺序 import**。
> 后者下 `before()` 钩子**不会触发**（根测试在第一个文件 import 完就开始跑了），
> `after()` 会。所以**别用 `before()` 装全局状态** —— `node-prelude.test.js`
> 在这里栽过两次：探针节点没装上、8 个用例全红，而且探针漏给后面的
> `node-registry.test.js`，把它的节点计数断言一起带崩。
> 现在的规矩是「谁改进程级注册表，谁在 `finally` 里还回去」。

最有价值的五个测试：

1. **真机 GLSL 编译**（`glsl-compile`）——抓到过 6 个只有编译器才能发现的 bug
   （缺 `#version`、uniform 带初始化器、重载返回类型不一致、常量类型不符、表达式不递归展开……）。
2. **GPU 像素回读**（`render-gpu`）——编译通过 ≠ 画得对。
   读回像素验证纹理真的绑上了、兜底路径走了、Buffer 反馈拿的是上一帧、
   iMouse 位置与公式精确吻合。
3. **真鼠标拖拽**（`editor-interaction` / `editor-history`）——抓到过一个**致命 bug**：
   `_onPointerUp` 先把 `this.drag` 清空、`_canDrop()` 又去读它，
   结果**手动连线从来没成功过**（编译过、单测过、模板看不出来）。
   撤销栈也是同一类问题：快照拍早一拍晚，单测看不出来，只有真的按下—拖动—松开才暴露。
4. **跨平台语义等价**（`cross-compile`）——转译最危险的地方是产出一段
   「看着很像、其实语义错了」的代码（矩阵静默转置、`mod` 换成 `fmod`、
   坐标原点翻两次）。肉眼看代码发现不了，只有**跑起来对数值**才露馅：
   拿全部示例的每个 pass，用同一套求值器跑原 GLSL 与转译后的 AST，
   要求 24 个采样点上逐位相等。**这一条也抓出过一个真 bug**（见下）。
5. **1080p 性能**（`perf-1080p`）——用 `EXT_disjoint_timer_query_webgl2` 拿
   **GPU 侧真实耗时**，而不是量 CPU 的 draw 调用（后者只有 0.03ms，说明不了问题）。

后四个在受限沙箱下会**自动跳过**而不是假失败。

### 实测性能（无头 Edge + SwiftShader 软件渲染，1920×1080）

| 场景 | rAF 帧率 | CPU `render()` p95 | GPU 单帧 p95 |
|---|---|---|---|
| 简单图（uv→渐变→调色板） | 139.7 FPS | 0.10 ms | **0.07 ms** |
| 重负载（fbm 4 层 + BufferA 多 Pass） | 143.9 FPS | 0.10 ms | **0.86 ms** |

60 FPS 的预算是 16.7 ms/帧，即软件渲染下也有约 20 倍余量。真机有独显只会更快。
页面隐藏时 1 秒内渲染次数 = **0**。

## 体积

按**真实依赖闭包**量（从入口顺着 `import` 走一遍），而不是按目录名圈一块 ——
目录名会把「面板根本不加载的东西」算进首屏。

| 部分 | 入口 | 文件数 | 源码 | gzip |
|---|---|---|---|---|
| 首屏 runtime（面板预览要用） | `client/runtime/index.js` | 10 | 140.9 KB | **42.3 KB** |
| 面板（挂载时才 `import()`） | `client/panel/index.js` | 21 | 372.0 KB | 109.4 KB |
| Host 侧（含资源层 + 转译器 + SPIR-V 编码器） | `host/index.js` | 23 | 394.1 KB | 117.9 KB |

第三方运行时依赖：**0**。

两个刻意的取舍，值得单独说：

- **转译器（`cross-compile` / `glsl-parse` / `spirv-gen` / `spirv` / `shadertoy-import` / `zip`）
  只在 Host 侧，面板一个都不 import**。面板导出走的是 HTTP action，
  所以浏览器那侧的首屏体积**没有被 FR-06 / FR-10 撑大**（面板自己的闭包也没变）。
- `shared/glsl-eval.js`（26.6 KB）是**只给测试用**的求值器，不参与运行时 ——
  它存在的唯一目的是让「转译前后逐点数值等价」这件事可验证。

### FR-06 落地细节

- **HLSL / MSL 是源码级转译**（`shared/glsl-parse.js` → `shared/cross-compile.js`），
  **SPIR-V 是 AST 直出二进制**（`shared/spirv-gen.js` + `shared/spirv.js`）。
  三条路都**不依赖任何外部 shader 工具链** —— 本机 `glslangValidator` /
  `spirv-cross` / `glslc` / `dxc` / `fxc` / `naga` / `tint` / `slangc` **一个都没有**，
  而项目要求零依赖 + 全离线，所以只能自己写。
- **三处最容易静默出错的地方**，每处都钉了测试：
  1. **矩阵序**：GLSL / MSL / SPIR-V 是列主序，HLSL 是行主序 →
     HLSL 侧 `mat2(a,b,c,d)` 要转置，SPIR-V 侧 `OpMatrixTimesVector` / `OpVectorTimesMatrix`
     要选对那一条（写反了不报错，只是画面镜像）。
  2. **`mod` ≠ `fmod`**：GLSL 的 `mod(x,y) = x - y*floor(x/y)`（y 为负时结果符号跟 y），
     HLSL 的 `fmod` 是截断语义。负数区间的差异肉眼看不出来，所以 MSL / HLSL 都改写成
     `$mod(...)` 形式而不是直接换名。
  3. **`gl_FragCoord` 的原点**：GLSL 左下、HLSL `SV_Position` 与 MSL `[[position]]` 左上。
     另外 GLSL 允许在**辅助函数里**读 `gl_FragCoord`，HLSL / MSL 不允许 ——
     所以那两种目标会**明确报错**（`fragcoord-in-helper`），而不是默默转译出一段错的代码；
     SPIR-V 允许（它是模块级 `Input` 变量），所以放行。
- **`mod` 改名这类纯文本变换，语义测试管不到 —— 这是实测出来的**：
  把 `mod` → `$mod` 的改名**故意去掉**，语义测试**一个都不失败**
  （求值器对两种写法都实现 GLSL 的 mod 语义）。
  所以 `cross-compile.test.js` 里额外钉了一组**文本断言**，两套一起才盖得住。
  这条结论写在测试文件头部，免得以后有人把文本断言当冗余删掉。
- **SPIR-V 的诚实边界**（写在 `shared/spirv.js` 头部、工具描述、返回值 `note` 和这里）：
  本机**没有 `spirv-val`**，所以这份二进制**没有经过官方校验器**。能保证的是：
  - 结构自洽：字长、id 界内、块终止、分支目标、先定义后使用（`validateSpirv`）；
  - 编码器与反汇编器**互为逆运算**（`roundTripSpirv` 逐字节相同）；
  - **喂给生成器的那棵 AST 语义没跑偏**（SPIR-V 目标用 GLSL 语义，所以能直接和原 GLSL 对数值）。
  不能保证的是**真机驱动会不会接受**。上真机前请在装了 Vulkan SDK 的机器上自己跑 `spirv-val`。
  同时输出一份 `.spvasm`（人读的汇编），方便用眼睛核。
- 实测：全部 8 个示例 / 12 个 pass 都能产出**结构合法、round-trip 逐字节相同**的 SPIR-V 模块。
  生成的 opcode 覆盖 `OpType*` / `OpConstant` / `OpFunction` / `OpVariable` /
  `OpAccessChain` / `OpCompositeConstruct` / `OpImageSampleImplicitLod` / `OpExtInst` /
  `OpLoopMerge` / `OpSelectionMerge` / `OpBranchConditional` / `OpDecorate` 等。
  （`music` 那两个 Pass 里全是 `texture(iChannel0, ...)` 采样，照样转得过去。）

### FR-10 落地细节

- **Shadertoy 导入落成「用户节点」而不是新材质类型**。工作台本来就有用户节点机制
  （`<工作区>/library/nodes/*.json`，定义里能带 `glslPrelude` + `code`），
  正好装得下「一整段自定义 GLSL」。走这条路，导入**不需要改 codegen、不需要新增材质类型**，
  预览 / 热重载 / 导出三条路也不用各写一遍，而且导入的 shader 立刻变成**可复用节点**。
- **切函数体不能数括号**：Shadertoy 代码的注释和字符串里出现 `{` `}` 很常见，
  朴素计数会切歪。`matchBrace()` 会跳过注释与字符串。测试里专门放了一段带注释花括号的源码。
- **包装成有返回值的函数**：Shadertoy 是 `out vec4 fragColor` + 无返回值，
  我们包成 `vec4 st_shadertoyMain(vec2 fragCoord)`，于是：
  - 裸的 `return;`（Shadertoy 允许提前退出）必须改写成 `return fragColor;`，
    否则 `vec4` 函数里裸 return 编译不过；
  - 源码自带的 `void main()` 会被**移除**（会和生成器产出的入口重名）；
  - 两条都会出现在返回的 `warnings` 里，不闷声改。
- **导入是覆盖式的**：会把目标材质的图整体换成「Shadertoy 节点 + `output` 终止节点」。
  解析在落盘之前完成，所以源码不对时返回 400 **且不会动材质**（有测试钉着）。
- **ZIP 打包器也是自己写的**（`shared/zip.js`，store 模式）。理由同上：不能为导出一个 zip
  拉 `archiver` / `jszip`。几个刻意的选择：
  - 文件名走 UTF-8 并置 EFS 位（`0x0800`），**中文文件名在别的解压器里不会乱码**；
  - 时间戳写成固定值 → **同样输入产出逐字节相同的包**，测试可以直接比字节；
  - 不写 zip64，条目数 / 总大小超限时**明确报错**，而不是悄悄产出一个坏包；
  - `readZip()` 是**自检工具**，会顺着中央目录把内容切出来核对 CRC。
    它证明包自洽，**不能替代真正的解压器** —— 文档里写明了这一点。

### FR-01 落地细节

- **撤销栈是快照式的**（`JSON.stringify(graph)`），不是逆操作式的。
  理由：图小（几十个节点），快照比给每个操作写一个逆操作简单得多、也不容易漏。
  代价是内存，所以做了**数量 + 字节双预算**（100 步 / 12 MB，至少保留最近 1 步）。
- **连续同类操作合并**：拖滑杆、连点微调在 700 ms 窗口内并成一步
  （合并键 `param:<nodeId>:<key>` / `uniform:<name>`），否则拖一次滑杆能塞几十步。
- **`_commit(label, fn)` 自动比对前后快照**，没真改就不入栈 ——
  所以「点一下已经选中的节点再松手」不会白占一步撤销。嵌套调用只在最外层入栈一次，
  于是「插入示例」= 一步撤销（而不是十步）。
- **还原是就地改图对象**（清键 + 覆盖），不换对象。
  图对象被工作台、参数面板、渲染器、热重载一起拿着，
  换对象会让它们继续对着被丢弃的那份干活（症状：撤销了、界面动了、存下去的却没撤）。
- **分组框 ≠ `group` 元节点**：分组框是**编辑器层的装饰件**（`passes[].frames`），
  只画在画布上、不参与代码生成，删框不会删框里的节点；
  `group` 元节点会真的改图语义（把子图封成一个可复用节点）。
  两者刻意分开：想要「视觉整理」用分组框，想要「复用」用 Group。
- 分组框**只有标题栏能拖**，框体内部穿透给框选 ——
  否则一块大框会把底下的节点全挡住、点不着。

### 资源系统落地细节（超出需求书）

需求书里没有这一块，是在做"音乐可视化"示例时长出来的：一开始只有"纹理"，后来音频、
歌词都得挂到材质上，索性统一成一套资源模型。

- **统一进 `resources[]`，类型由注册表决定**（`shared/asset-types.js`）：图片 / 音频 /
  歌词 / 视频四类的差异写成**数据**（扩展名、占不占槽位、单例、放哪个子目录），
  磁盘操作在 `host/asset-loader.js`、浏览器绑定在 `client/panel/asset-binder.js`。
  加一个类型 = 注册表加一条 + binder 加一条，loader 通常不用动。
- **旧的 `textures[]` / `audio` / `lyric` 只读兼容**：读时归并进 `resources[]`，
  写时不再输出。归并出来的 id 用「类型 + 路径」哈希，保证前后端算出来一致
  （用随机 id 的话，从旧字段归并来的资源一律 404）。
- **文字和音频都不进 shader**：歌词是叠在 canvas 上的 HTML 层（LRC 解析 + KTV 高亮），
  音频走 `<audio>` + `/asset` 流式端点。中文进 GLSL 要么预烤字体纹理、要么上 SDF，
  和 HTML 层比代价收益完全不成比例。
- **迁移事故（写在这免得重踩）**：资源统一到一半时，`workspace.js` 的
  `importTexture` / `unbindTexture` / `importAudio` / `clearAudio` / `clearLyric`
  还在写（或 `delete`）**已经被 `normalizeManifest` 移除的旧顶层字段** ——
  归一化对象上根本没有 `textures` / `audio` / `lyric`：

  | 方法 | 症状 |
  |---|---|
  | `importTexture` / `unbindTexture` | `undefined.filter(...)` → `TypeError`，导入直接崩 |
  | `importAudio` | 用了**没 import 的 `statSync`** → `ReferenceError`，导入直接崩 |
  | `clearAudio` / `clearLyric` | `delete` 一个不存在的属性 → 解绑静默失效 |
  | `readAudio` / `readLyric` | 读 `undefined` → "显式指定文件名"那一档永远走不到 |

  现在这些方法全部**委托给 `asset-loader.js`**（音频 / 纹理）或改用 `resources[]`（歌词），
  由 `tests/asset.test.js` 的 10 个用例（含逐条回归）守着。
- **解绑≠删除**：`clearAudio` / `clearLyric` / `asset.remove` 只从 `resources[]` 摘引用，
  **不删文件**。因为资源发现是"文件即事实来源"（扫目录也能认出文件），
  所以解绑后只要文件还在目录里，它就仍会被列出来 —— 这是刻意的语义，不是 bug。
  想彻底移除得用户自己把文件移出材质目录（插件永不删用户文件）。

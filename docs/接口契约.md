## 0. 硬性约束（违反即返工）

1. **零外部运行时依赖**。`package.json` 的 `dependencies` 必须为空。
   全部只用 Node 内置模块 + 浏览器内置 API。
2. **不引入构建链**。手写 ESM JavaScript，没有 TypeScript、没有打包器。
   Host 侧靠 Node 直接 import；Client 侧靠 Host 原样送出源码，浏览器原生 `import()`。
3. **ESM only**。`"type": "module"`。
4. **所有文件操作走 Host**。面板自己绝不碰磁盘，一律通过 HTTP API。
5. **路径必须做前缀校验**，不是「过滤特殊字符」。
   `Workspace.path()` 是唯一允许生成写路径的入口。
6. **永远不删除文件**。删材质是 `rename` 到 `.trash/`。
7. 核心 runtime（`client/runtime/`）不依赖 React、不依赖任何第三方库，
   必须能被 Node 直接 import 做单测（所以里面不能出现 `window` / `document` 的顶层引用）。

## 2. 数据模型

### 2.1 ShaderGraph

```ts
interface ShaderGraph {
  id: string
  name: string
  version: 1                       // GRAPH_FORMAT_VERSION
  nodes: GraphNode[]
  edges: GraphEdge[]
  uniforms: UniformDef[]
  passes: { name: PassName; graph: string[] | null }[]
  metadata: { version: string; tags: string[] }
}
type PassName = 'image' | 'BufferA' | 'BufferB' | 'BufferC' | 'BufferD'
```

**关键设计：节点是扁平的，Pass 只持有节点 id 列表。**
这样同一个节点可以被多个 Pass 引用，也避免了「同一个节点存两份」的同步问题。

```ts
interface GraphNode {
  id: string
  type: string                     // 节点库里的 type
  x: number; y: number             // 画布坐标
  params: Record<string, any>
  paramDefaults?: Record<string, any>  // 未接线输入的端口缺省值覆盖表
  annotation?: string
}
interface GraphEdge {
  id: string
  from: { node: string; port: string }   // 上游输出端口
  to:   { node: string; port: string }   // 下游输入端口
}
interface UniformDef {
  name: string                     // 必须匹配 /^[A-Za-z_][A-Za-z0-9_]*$/
  type: 'float' | 'vec2' | 'vec3' | 'vec4'
  value: number | number[]
  min?: number; max?: number       // 滑杆范围
  label?: string
  ui?: 'slider' | 'color' | 'angle'
}
```

### 2.2 MaterialManifest

```ts
interface MaterialManifest {
  id: string
  name: string
  graphPath: string                // 固定 'graph.json'
  shaderFiles: { frag: string; vert?: string }
  uniforms: Record<string, any>    // 参数快照
  resources: AssetRef[]            // 唯一的资源字段，见 2.2.1
  passes: PassName[]
  comfyWorkflows?: string[]        // M4 预留，本版恒为空
  tags: string[]
  updatedAt?: string               // ISO 8601
}
```

#### 2.2.1 资源引用（AssetRef）

图片 / 音频 / 歌词 / 视频**统一装在 `resources[]` 里**，形状由类型注册表
（`shared/asset-types.js`）决定：

```ts
interface AssetRef {
  id: string                       // 'as_xxx'；扫目录发现的用稳定哈希 'as_scan_xxx'
  type: 'texture' | 'audio' | 'lyric' | 'video'
  path: string                     // **相对材质目录**，POSIX 分隔符，绝不存绝对路径
  slot?: ChannelSlot               // 仅「占槽位」的类型才有
  label?: string
  meta?: Record<string, any>       // 类型特有数据（如纹理的 source / importedAt），不参与语义
}
type ChannelSlot = 'iChannel0' | 'iChannel1' | 'iChannel2' | 'iChannel3'
```

内置类型的约定：

| type | 扩展名 | 占槽位 | 默认槽 | 单例 | 放哪 |
|---|---|---|---|---|---|
| `texture` | png jpg jpeg webp bmp gif dds ktx ktx2 hdr | ✓ | `iChannel1` | | `textures/` |
| `audio` | mp3 flac wav ogg m4a aac opus | ✓ | `iChannel0` | | 材质根目录 |
| `lyric` | lrc txt | | — | ✓ | 材质根目录 |
| `video` | mp4 webm mov | ✓ | `iChannel2` | | 材质根目录 |

- **图片默认占 `iChannel1`、音频占 `iChannel0`** —— 这样两个都「丢进目录」也能同时挂上，
  不用手动改槽位。
- **歌词是单例**：同一材质只留一份，重复导入即替换；它也不占通道槽位。
- `path` 存相对路径是硬规定：换机器、换盘符都不会烂。

**旧字段（`textures[]` / `audio` / `lyric`）只读兼容。** 读的时候由
`normalizeManifest` 归并进 `resources[]`，写的时候不再输出 —— 于是老材质打开不丢东西，
新代码只有一套逻辑。归并出来的 id 用「类型 + 路径」哈希（**稳定**，见
`stableLegacyId`），这样「前端拿到的 id」和「服务端再读一次生成的 id」才对得上；
用随机 id 的话，所有从旧字段归并来的资源一律 404。

**`resources[]` 是权威来源，扫目录只是「未登记的候选」。** 用户直接把文件拖进材质目录、
不走导入，也能被 `asset.list` 扫出来（「丢文件即识别」），但**扫描结果不写回 manifest** ——
只有显式导入（`asset.import`）才登记。所以：

> **「解绑」摘的是引用，不删文件。** 只要文件还躺在材质目录里，它就仍会被扫出来、
> 仍会出现在资源列表里。想彻底移除，请自己把文件移出材质目录 —— 插件永不删用户文件。

回归防线：`tests/asset.test.js` 钉住「所有写入都落在 `resources[]` 上、
不许再碰那三个旧字段」，以及类型注册表、单例、同槽位只留最新等语义。

### 2.3 端口类型与连接规则

`float | vec2 | vec3 | vec4`。

**连接规则（`canConnect`）：任意两种合法类型都能连，4×4 全放行。**

> 这条踩过坑。v1 的规则是「同类型可连，float 与 vecN 之间可连」，
> 理由是「只有这些组合有意义」。但生成器的 `castExpr` 对 **16 种组合全都有确定规则**，
> 于是出现了两个后果：
> 1. `uv`(vec2) → `output`(vec4) 这种最基本的连法在 UI 上被拒绝，
>    用户想直连都没门，只能插一个「合成 vec4」节点；
> 2. 内置示例模板走 `_link()` 绕过了检查直接连 —— **UI 拦的连线，模板自己却在连**。
>
> **结论：编辑器的规则不能比生成器更严。** 有损与否由 `conversionKind` 描述，
> UI 该提示就提示（状态栏显示「会丢弃多余分量」），但不该阻止。

转换规则（生成器 `castExpr` 负责实现）：

| 方向 | `conversionKind` | 生成的代码 |
|---|---|---|
| 同类型 | `exact` | `x` |
| float → vecN | `broadcast` | `vecN(x)` 广播 |
| vecN → vecM（M>N） | `extend` | `vec4(x.x, x.y, 0.0, 1.0)` 补位 |
| vecM → vecN（N<M） | `truncate` | `vec2(x.x, x.y)` 截断 |
| vecN → float | `truncate` | `(x).x` 取第一分量 |
| 非法类型名 | `invalid` | — |

**第 4 位（alpha）补 1.0，不是 0.0。** 这条踩过坑：vec3 颜色提升成 vec4 时
alpha 补 0 会让整个画面全透明——而且**编译器不报错**，只有肉眼看画面才发现。

回归防线：`tests/codegen.test.js` 里有一组用例把「canConnect 放行的每种组合」
逐个喂给 `compileGraph`，两边不一致就会红。


`library/groups/` 存的是**组模板**（`group.save` 写）。从库里拖一个组出来时，
子图会被拷进新节点的 `params.graph`，所以改模板不影响已有实例。

工作区根目录解析优先级：

1. `config.workspaceRoot`（profile 的 `cordis.patch.yml`）
2. 环境变量 `DSH_SHADER_WORKBENCH_ROOT`
3. **`<DSH_HOME>/shader-workbench.json` 里的 `workspaceRoot`** ← 面板「存储位置」写的就是这个
4. Session 工作目录 `/shader-workbench`（仅工具；没有会话上下文的面板跟着"最近一次工具解析出的根"走）
5. 进程 cwd `/shader-workbench`

第 3 条是**面板和 agent 共用**的那一层。这不是可有可无的糖：没有它的时候，
工具（有会话上下文）和面板（走 HTTP，没有会话上下文）会算出**两个不同的根** ——
agent 把材质写进 A，用户打开面板看到的是 B（空的），资源树永远空、一堆按钮点了没反应。
面板会在资源树顶上显示当前用的是哪个根，并在被第 1/2 条压过时明确标出来。

## 4. 节点库契约

节点定义（`shared/nodelib.js`）：

```ts
interface NodeDef {
  type: string
  title: string                   // 中文显示名
  category: '输入'|'数学'|'向量'|'颜色'|'程序化'|'纹理'|'自定义'|'输出'
  doc?: string
  inputs: PortDef[]
  outputs: PortDef[]
  params: Record<string, ParamDef>
  code: string                    // **单个 GLSL 表达式**，禁止分号、禁止语句序列
  helpers?: string[]              // 需要哪些 GLSL_HELPERS
  glslPrelude?: string            // 节点自带的函数定义
  dynamicOut?: (params, ports) => PortDef[]   // 输出类型随参数变化（const / uniform）
  terminal?: true                 // 终点节点（output），一个 Pass 只能有一个
  split?: true                    // 多输出节点，各输出映射到输入的分量
  textureSample?: 'channel' | 'buffer'
}
interface PortDef { id: string; type: PortType; label: string; def?: any }
interface ParamDef { type: ParamType; value: any; label?: string; min?: number; max?: number; options?: string[] }
```

表达式占位符：

- `$in.<端口id>` → 该输入接上的表达式；没接线时用 `port.def`，
  其次用节点实例上的 `node.paramDefaults[端口id]`。
- `$p.<参数名>` → 参数值按类型序列化成 GLSL 字面量。
  **text 类型会递归展开**——`custom` 节点的表达式本身就是 `$in.a` 这种模板。

当前节点数：**57 个**（内置，只放通用件；效果专用节点随示例走，见 4.2）。

### 4.1 节点注册表（运行时可变）

`shared/nodes.js` 的 `NODE_LIBRARY` / `NODE_BY_TYPE` / `NODE_CATEGORIES`
是**同一批对象、原地重建**的（不是 `export let`，也不冻结）：

- 引用永远不变 → 所有已 import 的模块（宿主工具、生成器、面板）自动看到新节点；
- 内容会被 `setBuiltinNodes` / `setUserNodes` 改写，`nodeLibraryVersion()` 递增。

**别把它们改成重新赋值或重新冻结** —— 那会让"加节点要重启"这个坑回来
（宿主是静态 import，进程活着就永远拿着旧的那一份）。

取节点定义用 `getNodeDef(type)`；取端口（含动态端口）用
`resolvePorts(node, dir)` / `resolvePortType(node, dir, portId)`。

### 4.2 用户节点（`<工作区>/library/nodes/*.json`）

字段与内置节点一一对应：`type / title / category / doc / inputs / outputs /
params / glslPrelude / code / defaults`。校验规则（`shared/user-nodes.js`）：

- `type` 必须是标识符，且**不能和内置节点重名**（重名跳过并记进诊断）；
- `code` 里**不许有分号**（生成器写的是 `vec4 x = <表达式>;`，多语句请用 `glslPrelude`）；
- 端口类型必须属于 `PORT_TYPES`，参数类型必须属于 `PARAM_TYPES`；
- 单个文件写坏只影响它自己，错误带文件名回给 `nodelib.status.errors`。

宿主按「文件名 + mtime + size」签名判断要不要重读；面板用
`nodelib.status.userDefs` 在浏览器侧调 `setUserNodes()` 对齐。**都不需要重启。**

**效果专用节点随示例走。** 只服务某一个效果的节点（`ifsTunnel` / `fourierSeries` /
`epicycles`）不该进内置库 —— 它们放在 `examples/<示例>/library/nodes/*.json`，
`example.load` 会连项目一起装进 `<工作区>/library/`（返回值的 `library[]` 列出装了哪些）。
同一个节点被两个示例各带一份是允许的，按 `<type>.json` 落文件，本来就是同一份。

### 4.3 组（Group）元节点

| 类型 | 端口 | 说明 |
|---|---|---|
| `group` | **动态**：来自 `params.graph.inputs/outputs` | 画布上的那颗"打包好的节点"；`params.repeat > 1` 时是**循环** |
| `loopIndex` | 出 out(float) | 重复组循环体里的当前轮次（从 0 起）；放在循环体外报 `loop-index-outside` |
| `groupInput` | 出 out | 子图内部的入口，`params.port` 对应组的一个输入端口 |
| `groupOutput` | 入 color | 子图内部的出口，`params.port` 对应组的一个输出端口 |

`params.graph` 的形状：

```json
{ "name": "…", "inputs": [{ "id", "label", "type" }], "outputs": [{ "id", "label", "type" }],
  "nodes": [ …子图节点… ], "edges": [{ "from": { "node", "port" }, "to": { "node", "port" } }] }
```

**子图是内联的**，不是引用外部文件：材质自包含，宿主与浏览器两侧的生成器
各自递归展开即可，不需要共享解析器；改模板也不会影响已有实例。

`repeat > 1` 时是**循环**（重复是语言结构，不是复制）：

```json
{ "repeat": 99,
  "carries": ["dist", "acc", "acc2"],   // 跨迭代传递的量（默认取 inputs ∩ outputs）
  "inputs":  [{ "id": "ray" }, { "id": "dist" }, …],
  "outputs": [{ "id": "dist" }, …] }
```

生成的样子：carry 变量在循环外声明（初值 = 该输入端口接的外层表达式），
`for (int i = 0; i < 99; i++) { <循环体>; carry = <轮末值>; }`，组的输出 = carry 变量。
循环体里放 `loopIndex` 节点即可拿到轮次，用来把"第几段"写成公式
（贝塞尔的 24 段就是这么做的，不用复制 24 份）。
重复组**不能「拆开组」**（拆开就丢循环了）：把「重复次数」改成 1 再拆。

生成器的展开规则（`codegen.js` 的 `buildGroup`）：把子图节点/连线的 id 加上
`<组节点id>::` 前缀并进当前 Emitter，子图里的 `groupInput` 表达式由外层输入代入，
组的输出端口取对应 `groupOutput` 的 `color` 输入。嵌套上限 8 层。错误码：

| code | 场景 |
|---|---|
| `empty-group` | 组还没有内容（刚拖出来还没打包） |
| `unknown-group-port` | 外层连到了组没声明的端口 |
| `group-output-missing` | 声明了输出端口，但子图里没有对应的 `groupOutput` |
| `group-too-deep` | 嵌套 > 8 层 |
| `group-input-outside` | `groupInput` 被放到了组外面 |

## 5. 代码生成契约

`compileGraph(graph, passName, opts)` → 

```ts
{
  ok: boolean
  code: string          // 完整可编译的 GLSL ES 3.00 片元着色器
  body: string          // void main() { ... }
  header: string        // #version + precision + uniform 声明
  helpers: string[]     // 用到的 helper 名（依赖闭包已展开）
  channels: string[]    // 用到的 iChannel
  buffers: string[]     // 用到的 Buffer 采样
  uniforms: { name, type, init, inferred? }[]
  errors: { code, message, pass? }[]
  warnings: string[]
}
```

生成的着色器形态：

```glsl
#version 300 es                     // 必须是第一行，前面不能有空行
precision highp float;
precision highp int;

uniform vec3 iResolution;
uniform float iTime;
uniform float iTimeDelta;
uniform int iFrame;                  // 仅 Buffer Pass
uniform vec4 iMouse;
uniform vec4 iDate;
uniform sampler2D iChannel0;         // 仅用到时声明
uniform sampler2D BufferA;           // 仅用到时声明
uniform float uSpeed;                // 不带初始化器！ES 3.00 不允许

out vec4 st_fragColor;

float st_hash(vec2 p) { ... }        // 仅用到的 helper

void main() {
  vec2 n_uv0 = gl_FragCoord.xy / iResolution.xy;
  st_fragColor = vec4(...);
}
```

**四条踩过的坑，写进契约：**

1. `#version 300 es` 必须是文件第一行。缺了编译器退回 ES 1.00，
   `in/out`、`texture()` 全部报错。
2. **GLSL ES 3.00 的 uniform 声明不能带初始化器**，
   写了报 `cannot initialize this type of qualifier`。
3. `const` / `uniform` 这类「表达式就是 `$p.x`」的节点，
   必须按**输出端口类型**重新序列化值——否则 `float x = vec3(...)` 编译不过。
4. 函数重载的返回类型必须一致，不能把 `float st_pow` 和 `vec4 st_pow` 混在一个重载集里。

错误码：

| code | 含义 |
|---|---|
| `empty-pass` | Pass 里没有节点 |
| `no-output` | Pass 里没有 output 节点 |
| `cycle` | 节点图成环 |
| `unknown-node` | 不认识的节点 type |
| `missing-node` | 连线指向不存在的节点 |

## 6. 渲染器契约

`new ShaderToy(canvas, config)`：

```ts
class ShaderToy {
  setPass(name: PassName, fragmentSource: string): { ok, errors, shaderLog? }
  setGraph(graph: ShaderGraph, opts?): { ok, errors, compiled }
  setChannel(slot: string, source: TexImageSource | WebGLTexture | null): boolean
  setUniform(name: string, value: number | number[], type?: PortType): void
  setUniforms(values: Record<string, any>): void
  start(): void
  stop(): void
  step(): void
  render(dt: number): void
  attachMouse(): () => void          // 返回解绑函数
  stats(): object
  dispose(): void
}
```

- 顶点着色器用 `gl_VertexID` 生成全屏三角形，不需要 VBO。
- Buffer Pass 用 RGBA16F 双缓冲乒乓（需要 `EXT_color_buffer_float`）。
- **所有 Pass 必须全部编译成功才整体替换**。失败时保留上一份能跑的 program，
  错误进 `errors` 并回调 `onError`。这是 Shadertoy 的体验，也是必须的——
  改一半必然编译不过。
- 页面 `document.hidden` 时跳过渲染（满足「隐藏时 CPU < 1%」）。

### 6.1 iMouse 口径

| 分量 | 含义 |
|---|---|
| `xy` | 最近一次按下的位置（像素，y 向上）；从没按过则取负 |
| `zw` | 当前拖动位置；在画布外则取负 |

### 6.2 热重载契约

`new HotReload({ renderer, graph, debounceMs })`：

- 默认防抖 **120 ms**（需求书要求「变更后 500ms 内完成热重载」，
  500ms 是上限不是目标值；一次真实重载通常 1–5 ms）。
- `invalidate(graph, extra)` 返回 Promise，合并窗口内的多次改动。
- 失败不推翻画面，只把错误抛给 UI。

`workspaceRoot` 传空串 = 清掉、回到自动推断；必须是绝对路径，否则 400。
`overriddenBy` 为 `config` / `env` 时表示上层压过了这里的设置，UI 要如实提示。

`shader.write` 把一段 GLSL 正文落进材质目录（面板「导入材质文件」选 `.frag` 时用），
只接受 `.frag` / `.glsl`。**它写进去的文件不参与预览** —— 预览只渲染节点图生成的代码。

`asset.*` 是**统一资源 API**（类型注册表见 2.2.1）。`asset.list` 返回的是
「清单登记的 ∪ 扫目录发现的」两路并集，按 `path` 去重；扫到的"未登记候选"**不写回清单**。
`asset.import` 负责把磁盘文件拷进材质、按类型落对子目录（`texture` → `textures/`，
其余 → 材质根目录）、同槽位只留最新、单例类型只留一份。`asset.remove` 只从
`resources[]` 摘引用 —— **不删文件**。

`texture.import` / `audio.import` 是 `asset.import` 的语义化包装，**内部直接委托**
给 `importAsset`，所以引用一律落在 `resources[]`。`lyric.import` 特殊一点：
它收的是**正文文本**（面板里粘 / 选进来的歌词），写固定文件 `lyric.lrc` 后
登记一条 `lyric` 资源。

`audio.read` / `lyric.read` 都是「**先看 `resources[]` 里登记的，找不到再扫材质目录**」。
第二档是给「用户直接把文件丢进目录」用的（文件即事实来源）—— 所以**解绑之后，
只要文件还在目录里就仍然读得到**，这是刻意的，不是 bug（详见 2.2.1）。

> ⚠️ **本版的一次教训**：资源统一进 `resources[]` 时，`workspace.js` 里
> `importTexture` / `unbindTexture` / `importAudio` / `clearAudio` / `clearLyric`
> 一度还在写（或 `delete`）**已经被移除的旧顶层字段** —— 归一化对象上根本没有
> `textures` / `audio` / `lyric`，于是导入直接崩、解绑静默失效。
> 现在这些方法全部委托给 `asset-loader.js`，由 `tests/asset.test.js` 守着。

`example.*` 管的是**插件自带的示例**（`examples/<名字>/`，随包分发，见
[`examples/README.md`](../examples/README.md)）。载入 = 把整棵示例目录拷进
`<工作区>/projects/<名字>/`，形状与工作区一致，所以示例里调好的参数、清单、
预览图原样保留。同名已存在时返回 409 `example-exists`，要覆盖得显式带
`overwrite: true`；名字只允许字母数字下划线连字符（挡路径穿越）。

`material.export` 走的是**导出目标注册表**（`shared/cross-compile.js` 的
`registerExportTarget`），所以面板不该写死目标列表 —— 先调 `material.exportTargets`。
当前注册了 5 个：`glsl`（`shader.frag`）、`hlsl`（SM 5.0）、`msl`（Metal）、
`spirv`（`.spv` 二进制）、`spvasm`（人读的 SPIR-V 汇编）。
二进制目标额外回一份 `data`（base64）给面板触发下载，并带 `note` 说明边界。

> ⚠️ **SPIR-V 的诚实边界**：`.spv` 由本插件**自己手写**的编码器产出，本机
> **没有 `spirv-val`**，所以只做过结构自洽校验（字长、id 界内、块终止、分支目标、
> 先定义后使用）+ 编码/解码互逆，**没有经过官方校验器**。上真机前请在装了
> Vulkan SDK 的机器上自己跑一遍 `spirv-val`。

`material.importShadertoy` 做两件事：把包装好的 GLSL 落成**工作区级用户节点**
（`<工作区>/library/nodes/<type>.json`，于是别的材质也能拖出来用），
再把目标材质的图**整体换成**「Shadertoy 节点 + `output` 终止节点」。
换图是覆盖式的 —— 想要旧图请先打快照。找不到 `mainImage()` 时返回 400，
**且不会动材质**（先解析、后落盘）。

`material.exportZip` 用插件自带的零依赖打包器（`shared/zip.js`，store 模式），
条目约定：`说明.txt` 在最前，其后是 `<材质名>/<相对路径>`。文件名走 UTF-8（EFS 位），
时间戳是固定值 —— 所以**同样的材质打出逐字节相同的包**。

### 7.3 `GET /texture?project=&material=&path=`

送纹理原始字节。`path` 必须是材质目录内的相对路径，含 `..` 或绝对路径一律 400。

### 7.4 `GET /module/<相对路径>.js`

原样送出 `client/` 或 `shared/` 下的 ESM 源码，给面板 `import()` 用。
只允许 `.js` / `.mjs`，路径解析后必须落在白名单根目录内。

**白名单有三个根**：`client/`、`shared/`、插件根。为什么不止 `client/`：

```
磁盘：  client/panel/foo.js  ── import '../../shared/graph.js' ──→  shared/graph.js
URL：   /module/panel/foo.js ── 浏览器解析 ../../ ────────────→  /shared/graph.js
```

URL 里的 `module/` 那一层把深度对不上了。所以路由**不能按 URL 层级切目录**，
而是把 `module/` 后面的整条路径拼成物理路径再 `normalize`：
`module/panel/../../shared/graph.js` → `shared/graph.js`。
为了兼容解析后丢掉 `module/` 的 URL，另外补了一条 `/shared/*` 别名路由。

### 7.5 面板模块加载时序

```
client/index.js（__ModuleLoader__ 载荷）
  └── apply(ctx)  →  slots.inject('sidebar.panellist') / slots.inject('main')
                     （挂一个只有生命周期、没有内容的 React 组件）
        ↓ 用户点侧栏那一行，main 槽位挂载
  WorkbenchPanel  useEffect  →  import('/plugins/<id>/module/panel/index.js')
        →  mod.ensureStyles()  （注入 <style>，只注一次）
        →  mod.mountWorkbench(host)
              →  异步 import 其余 panel 模块 + runtime + shared
              →  new Workbench() → .mount(host)
        →  卸载时 mod.disposeWorkbench()（释放 WebGL、rAF、事件监听）
```

面板内容**全部是原生 DOM**，React 只拿到一个空容器。理由见架构说明第 2.5 节。

## 8. Host 工具契约（给 agent 用）

工具统一返回 `{ ok, ... }`，**永不抛错**（`guard()` 包一层）。

| 工具 | 作用 |
|---|---|
| `shader_node_library` | 返回完整节点库手册（type / 端口 / 参数 / 默认值 / doc） |
| `shader_workspace` | 工作区概览（根目录、项目、材质数） |
| `shader_project` | 项目的 list / create / read |
| `shader_material` | 材质的 list / create / read / save / archive |
| `shader_graph_build` | 用「友好写法」建图并落盘（支持 dryRun） |
| `shader_compile` | 只做代码生成，可写 cache |
| `shader_export` | 编译一个 Pass 并转译成目标格式，写进材质目录。`target` 的枚举**由注册表生成**（`glsl` / `hlsl` / `msl` / `spirv` / `spvasm` / `json`），默认 `glsl` |
| `shader_export_targets` | 列出当前注册的导出目标 `{ id, label, extension, binary }`（注册表可扩展，所以这是权威列表） |
| `shader_shadertoy_import` | 贴一段 Shadertoy 源码 → 落成用户节点 + 把材质图换成导入结果 |
| `shader_snapshot` | 快照 create / list / restore |
| `shader_texture_import` | 把磁盘上的图拷进材质并绑通道 |

`shader_export` 的 `spirv` 目标返回 `{ ok, target, path, fileName, binary:true, bytes, note }`；
`json` 目标是「图 + 清单」的自包含 bundle。`spirv` 的 `note` 里明确写着
**这份二进制没经过 `spirv-val`** —— 工具描述里也写了，别把它当成已验证的产物。

`shader_shadertoy_import` 会**替换**目标材质的图。源码自带的 `void main()` 会被移除
（会和生成器产出的入口撞名）、裸的 `return;` 会被改写成 `return fragColor;`，
两条都会出现在返回的 `warnings` 里。用到的 `iChannel*` / `Buffer*` 也会一并回报，
方便接着绑纹理。

`shader_graph_build` 的友好写法：

```json
{
  "project": "demo",
  "material": "plasma",
  "nodes": [
    { "id": "uv0", "type": "uv", "x": 0, "y": 0 },
    { "id": "out0", "type": "output", "x": 400, "y": 0 }
  ],
  "edges": [{ "from": "uv0.out", "to": "out0.color" }],
  "uniforms": [{ "name": "uSpeed", "type": "float", "value": 1.5 }],
  "passes": { "image": ["uv0", "out0"] }
}
```

边的引用写 `节点别名.端口id`；没给 `id` 别名时必须用真实节点 id。

## 9. 客户端插件契约

`package.json`：

```json
"dsh": {
  "engines": { "dsh": ">=0.2.0-rc.2" },
  "bundle": { "patch": "./cordis.patch.yml" },
  "client": {
    "inject": ["@deepseek-ai/dsh-client-ui-slots", "@deepseek-ai/dsh-client-ui-layout", "@deepseek-ai/dsh-client-ui-sidebar"],
    "platform": "web"
  }
}
```

`client/index.js` 必须是 `window.__ModuleLoader__.load({ id, factory })` 形式，
导出的 `factory(require)` 返回 `{ name, inject, apply }`：

- `inject = ['slots']` —— 只需要槽位服务。工作台数据全走 HTTP API，
  所以**不注入会话 / 工作区控制器**，宿主版本变化时更不容易卡住。
- `apply(ctx)` 通过 `ctx.slots.inject(key, cb)` + `ctx.slots.register(options, component)` 注册：
  - `sidebar.panellist`：`{ name, id: 'shader-workbench', order: 24, label }` + 图标组件
  - `main`：`{ name, key: 'shader-workbench' }` + 面板组件
- 两处注册分别 try/catch：宿主没有对应槽位时退化成「只有侧栏」或「只有主面板」，
  **绝不让插件进入 failed 状态**。

**React 用法约定**：面板内容用原生 DOM 自管，只借 React 的挂载/卸载生命周期。
理由：工作台里全是 canvas / WebGL / 拖拽这类命令式状态，
套进 reconcile 只会互相打架（重渲染会把 canvas 干掉）。

### 9.1 节点编辑器的公开 API

`NodeEditor` 除了 `setGraph` / `addNode` / `deleteSelected` 这些编辑方法，
还暴露两个**坐标查询**方法。它们不是测试专用钩子——外部拖拽、自动化、
手柄吸附、tooltip 定位都需要「某个端口在屏幕上的哪个位置」。

```ts
class NodeEditor {
  /** 世界坐标 → 画布内屏幕坐标 */
  toScreen(x: number, y: number): { x: number; y: number }

  /**
   * 某节点某端口在**视口坐标系**下的位置
   * （= 画布内坐标 + 画布在页面里的偏移，也就是 CDP / elementFromPoint 用的那套）
   */
  portPosition(nodeId: string, dir: 'in' | 'out', portId: string): { x: number; y: number } | null

  /** 某节点标题栏中心点在视口坐标系下的位置（拖节点时按这里最稳） */
  nodeHeaderPosition(nodeId: string): { x: number; y: number } | null
}
```

另导出纯几何函数 `measureNode(node)` 与常量 `NODE_WIDTH` / `HEADER_HEIGHT`，
外部不必硬编码节点尺寸。

**注意**：节点被拖动之后，之前取到的端口坐标就失效了——
每次要用之前都现取一次。（这条不是理论：写交互测试时踩过，
拿旧坐标去按下，结果打在被拖空的画布上，走了框选。）

### 9.2 资源绑定器（asset-binder）

`client/panel/asset-binder.js` 负责把「资源」从材质挂到 viewer 上，和
`host/asset-loader.js` 一一对应：

| 层 | 文件 | 管什么 |
|---|---|---|
| Host | `host/asset-loader.js` | 文件 从磁盘 → 材质（Node 环境） |
| Client | `client/panel/asset-binder.js` | 资源 从材质 → viewer（浏览器环境） |

每个类型的绑定行为写在自己的 handler 里：

- `texture` → `new Image()` → `renderer.setChannel(slot, img)`
- `audio`   → `new Audio()` → `renderer.attachAudio(audio)`
- `lyric`   → `fetch` 文本 → `lyrics.loadText(text)`

资源字节走**通用端点** `/plugins/<id>/asset?id=<assetId>`（不把路径暴露到 URL 里），
host 侧按 manifest 反查类型给 MIME。

`bindAssets(ctx, { project, material, resources, apiBase })` 返回一个 `dispose()`，
卸载材质时调用它释放 Image / Audio / 事件监听。

**加一个新类型**（比如 `video`）：`shared/asset-types.js` 加一处 `defineAssetType`，
这里加一个 `ASSET_BINDERS` 条目 —— `host/asset-loader.js` 通常不用改（走通用逻辑）。

## 10. 事件总线

```ts
type WorkbenchEvent =
  | 'graph:changed'      { graphId }
  | 'graph:opened'       { graphId }
  | 'material:updated'   { materialId }
  | 'material:deleted'   { materialId }
  | 'texture:imported'   { materialId, ref }
  | 'comfy:started'      { workflowId }        // M4 预留
  | 'comfy:done'         { workflowId, files } // M4 预留
  | 'compile:done'       { ok, durationMs }
  | 'compile:failed'     { errors, durationMs }
  | 'preview:hotreload'  { graphId, durationMs }
  | 'workspace:changed'  {}
```

事件名写错会在 `emit` 时抛错，不静默丢弃。监听器抛错被捕获记进 `errors`，不影响其它监听器。
